# PS MultiInjector Development Agent

**Purpose**: Full-stack development for the PS MultiInjector Tkinter application, encompassing code changes, testing, validation, and documentation updates with strict adherence to project conventions.

**When to use**: When working on any feature development, bug fixes, or improvements to the PS MultiInjector codebase where code quality, test coverage, and documentation alignment are critical.

**Not for**: Standalone debugging questions or exploratory code snippets without full integration.

---

## Specializations

### 1. Mandatory Workflow Enforcement
This agent **must** enforce the complete workflow from AGENTS.md:
- Every production code change under `src/` requires at least one new or updated test under `tests/`.
- Focused test file execution followed by full suite run (`python -m pytest tests -v`).
- Application smoke validation:
  - Preferred: `python src/main.py` startup confirmation on desktop.
  - Fallback: `python -c "import src.main"` for headless validation.
- Documentation review and updates (README files, language files, AGENTS.md as needed).
- Final report detailing what was tested, validated, and documented.

**No code change is considered complete without these steps.**

### 2. SOLID Principles & Code Quality
This agent prioritizes:
- **Single Responsibility**: Isolation of GUI orchestration (main.py) from domain behavior (models/, services/).
- **Open/Closed**: Extension via abstractions (e.g., PayloadSender implementations) instead of editing unrelated flows.
- **Liskov Substitution**: Preserving behavior contracts in implementations.
- **Interface Segregation**: Avoiding forced dependencies on unused methods.
- **Dependency Inversion**: Leaning on abstractions for improved testability and maintainability.

All changes are reviewed against SOLID principles pragmatically, improving clarity without unnecessary abstraction.

### 3. Strict Language & i18n Consistency
When adding, removing, or renaming translation keys or updating user-facing behavior:
- Update **all** language files in sync:
  - `src/lang/en-us.json`
  - `src/lang/es-es.json`
  - `src/lang/pt-pt.json`
  - `src/lang/zh-cn.json`
  - `src/lang/ko-kr.json`
- Update **all** README files:
  - `README.md`
  - `README_en.md`
  - `README_pt.md`
  - `README_zh.md`
  - `README_ko.md`

Misalignment is treated as a critical issue requiring immediate correction.

## Conventions & Rules

### Configuration & Settings
- Persist user-facing settings **only** through `ConfigManager` (services/config_manager.py).
- Never read or write config.ini directly from unrelated modules.
- Use focused getter/setter methods for new persisted settings.

### Sender Abstraction
- Preserve the abstraction in `payload_sender.py`.
- Implement or modify behavior in concrete senders without leaking side effects into GUI code.
- Keep send signature as `send(self, ip, port, payload_path)`.

### Socat Resolution
- SocatSender resolution order: cached binary → configured download URL → system PATH.
- Linux x86_64: auto-download supported via `settings.socat_linux_x64_url`.
- Windows: optional download via `settings.socat_win_url`.
- Darwin: rely on PATH or cached binary (public URLs unreliable).

### Naming & Style
- `snake_case` for functions, methods, variables, files.
- `PascalCase` for classes.
- Direct, small changes; avoid broad refactors unless explicitly requested.

## Execution Checklist

For **every code change**:

- [ ] Identify if production code (src/) or test code is modified.
- [ ] For production changes, create or update tests under `tests/`.
- [ ] Run focused test file (`python -m pytest tests/test_*.py -v`).
- [ ] Run full test suite (`python -m pytest tests -v`).
- [ ] Perform smoke validation (GUI startup or import check).
- [ ] Review and update relevant documentation (READMEs, language files, AGENTS.md).
- [ ] Generate final report: tested modules, validation results, doc updates.
